# 면접 예상 질문: CTR 예측과 보정 (5부)

답은 먼저 소리 내어 직접 말해 보고, 그다음에 읽으세요. 숫자는 `results/ctr/results.md` 기준입니다.

## 모델

**Q1. LR, FM, DeepFM, DCN-v2의 차이를 한 줄씩?**
- **LR:** 특성마다 가중치를 더합니다. "이 사용자는 후하다", "이 영화는 좋다"처럼 따로따로의 효과만 봅니다.
- **FM:** 특성마다 작은 벡터(임베딩)를 두고, 모든 쌍의 내적을 더합니다. "여성 × 드라마"처럼 짝의 효과를 봅니다. 데이터에 그 짝이 드물어도 벡터를 공유해서 추정할 수 있습니다.
- **DeepFM:** FM에 MLP를 병렬로 붙여, 더 복잡한 조합을 학습합니다.
- **DCN-v2:** Cross layer가 x₀ ⊙ (W xₗ + b) + xₗ로 차수를 하나씩 올린 명시적 상호작용을 만들고, MLP와 합칩니다.

**Q2. FM의 쌍별 상호작용 계산이 왜 O(kn)인가요?**
Σᵢ<ⱼ ⟨vᵢ, vⱼ⟩ = ½[(Σᵢ vᵢ)² − Σᵢ vᵢ²]이기 때문입니다. 모든 쌍을 돌지 않고 합의 제곱에서 제곱의 합을 빼면 됩니다.

**Q3. 결과는? 딥 모델이 왜 이기지 못했나요?**
AUC는 FM 0.8375, DeepFM 0.8345, LR 0.8333, DCN-v2 0.8270입니다. FM − LR(+0.0042)과 DeepFM − FM(−0.0030) 모두 유의하지 않았습니다.
LR에도 user_id·movie_id 가중치가 있어서 "사용자의 후한 정도 + 영화의 품질"을 이미 잡습니다. 평점 데이터에서는 그게 대부분이라, 상호작용이 더할 몫이 작았습니다. 딥 모델은 1~4 epoch 만에 과적합했습니다.

**Q4. 하이퍼파라미터를 튜닝했으면 딥 모델이 이기지 않았을까요?**
그럴 수 있습니다. 그래서 "같은 고정 예산에서의 비교"라고 한계에 적었습니다. 다만 FM보다 AUC가 낮았고 CI 상한도 +0.0001이라, 튜닝으로 생길 이득은 크지 않을 것으로 봅니다. 실무라면 정규화·dropout·임베딩 차원을 valid로 튜닝한 뒤 다시 비교하겠습니다.

## 평가

**Q5. 왜 랜덤 분할 대신 시간순 분할?**
서비스는 과거로 학습해 미래에 씁니다. 랜덤 분할은 미래 행동이 학습에 섞여 성능을 부풀리고, 신규 사용자 유입 같은 분포 변화를 숨깁니다. 실제로 시간순 분할에서는 valid의 77%가 신규 사용자였고, 이게 보정 실패(C3)의 원인이었습니다. 랜덤 분할이었다면 이 문제를 못 봤을 겁니다.

**Q6. 왜 사용자 단위 cluster bootstrap?**
같은 사용자의 행들은 서로 비슷합니다(후한 사용자는 전부 높게 줌). 행을 독립으로 보고 bootstrap하면 실제보다 표본이 많은 것처럼 계산되어 CI가 너무 좁아집니다. 그래서 사용자를 단위로 다시 뽑고, 뽑힌 사용자의 행을 통째로 넣었습니다.

**Q7. AUC와 LogLoss, ECE는 무엇이 다른가요?**
- **AUC:** 순서만 봅니다. 확률을 모두 2배로 늘려도 같습니다.
- **LogLoss:** 확률 값 자체의 품질을 봅니다.
- **ECE:** 예측값 구간별로 "예측 평균"과 "실제 비율"의 차이를 평균한 보정 오차입니다.

광고 경매는 pCTR × 입찰가로 순위를 정하므로, AUC가 같아도 확률이 틀리면 돈이 틀린 곳으로 갑니다.

## 보정

**Q8. Platt scaling이 뭔가요? 왜 AUC는 안 바뀌나요?**
예측 확률의 로짓 z에 a·z + b를 적용하고 시그모이드로 되돌리는 2-파라미터 로지스틱 회귀입니다. 단조 변환이라 순서가 그대로이므로 AUC가 같습니다.

**Q9. 그런데 왜 보정이 오히려 나빠졌나요?** (가장 중요한 질문)
보정용 valid 기간은 신규 사용자가 77%, test는 기존 사용자가 81%였습니다. 모델은 기존 사용자에게 이미 잘 맞았지만(ECE 0.0107), 신규 사용자는 과소 예측했습니다(예측/실제 0.935). valid 전체로 Platt을 맞추면 신규 사용자에 맞춰 예측을 올리고(b = 0.407), 그 보정이 기존 사용자 위주의 test에서는 과대 예측이 됩니다. ECE가 0.0180 → 0.0452로 나빠졌습니다.
교훈은 "**보정 데이터는 서빙 트래픽 구성과 맞아야 한다**"입니다. 신규·기존 사용자를 따로 보정하거나, 신규 여부를 특성으로 넣는 것이 안전합니다.

**Q10. 그 원인 분석은 사전 등록에 있었나요?**
아니요, 결과를 본 뒤의 사후 분석이라 따로 표시했습니다. 기존 사용자만으로 보정하면 test ECE 변화가 −0.0060 [−0.0094, +0.0014]로 유의하지 않았습니다. 원래 모델이 이미 잘 맞았다는 뜻입니다.

**Q11. 실서비스에서 보정이 깨지는 다른 이유는?**
- 음성 샘플링: 학습 때 음성을 줄이면 확률이 부풀어서, 역가중으로 되돌려야 합니다.
- 기준 반응률 변화: 계절, 이벤트, UI 변경
- 노출 위치 편향
- 모델 업데이트 주기와 트래픽 구성 변화

그래서 세그먼트별 "예측 합 / 실제 합"을 대시보드로 계속 봐야 합니다.

## 콜드 스타트

**Q12. 신규 사용자는 어떻게 했나요?**
user_id가 학습에 없으면 "모름" 인덱스로 보내고, 성별·나이·직업 같은 속성과 영화 쪽 특성으로 예측합니다. 신규 사용자 AUC는 0.8042로 기존(0.8446)보다 0.040 낮았습니다. ID를 다 빼면 신규 사용자 AUC가 0.1241 더 떨어졌는데, 신규 사용자에게 user_id는 원래 쓸모가 없으니 이 몫은 movie_id(영화 품질)입니다. 콜드 스타트에서도 아이템 신호가 가장 중요했습니다.

**Q13. 당근이라면 신규 사용자에게 무엇을 더 쓰겠어요?**
가입 직후의 동네, 첫 검색어·첫 조회 카테고리 같은 세션 신호를 특성으로 넣겠습니다. 처음 몇 번의 행동으로 빠르게 업데이트되는 순서 모델(2부의 SASRec 같은)도 후보입니다. 그리고 신규 사용자 구간의 보정을 따로 모니터링하겠습니다.
